# NetStego -- Система стеганографического сокрытия данных в сетевых пакетах

## 1. Общее описание

NetStego -- программная система для стеганографического сокрытия данных в заголовках и полях сетевых пакетов протоколов TCP/IP, с интегрированным модулем обнаружения скрытых каналов и анализа вредоносных вложений.

Система реализует полный цикл: шифрование данных, фрагментация, кодирование в сетевые пакеты, передача по сети, приём, декодирование, сборка и расшифровка. Параллельно функционирует модуль детекции, позволяющий анализировать трафик на наличие стеганографических каналов и подозрительного содержимого.

## 2. Архитектура

### 2.1 Pipeline передачи данных

```
Файл -> [Шифрование AES-256-GCM] -> [Фрагментация NST] -> [Фреймирование] -> [Кодирование в канал] -> [Отправка]
                                                                                                         |
Файл <- [Расшифровка AES-256-GCM] <- [Сборка фрагментов] <- [Разфреймирование] <- [Декодирование] <- [Приём]
```

### 2.2 Модули системы

| Модуль | Назначение |
|--------|-----------|
| `netstego.core.crypto` | AES-256-GCM шифрование, Argon2id KDF, генерация ключей |
| `netstego.core.fragmentation` | NST-протокол фрагментации (17-байтный заголовок, CRC32, SHA-256) |
| `netstego.core.reassembly` | Сборка фрагментов с дедупликацией, верификацией CRC32 и SHA-256 |
| `netstego.channels.*` | 5 стеганографических каналов (ICMP, IP ID, TCP ISN, DNS, TCP TS) |

| `netstego.cli` | CLI-интерфейс (7 команд) |

## 3. Стеганографические каналы

| Канал | Поле-носитель | Бит/пакет | Пропускная способность | Устойчивость к обнаружению |
|-------|--------------|-----------|----------------------|---------------------------|
| **ICMP Payload** | Payload ICMP Echo Request | 11 776 | Высокая | Низкая (аномальный размер) |
| **IP ID** | Поле Identification IPv4 | 16 | Очень низкая | Средняя |
| **TCP ISN** | Initial Sequence Number TCP SYN | 32 | Низкая | Средняя |
| **DNS QNAME** | Поддомен DNS-запроса (base32) | 240 | Средняя | Низкая (длинные метки) |
| **TCP Timestamp** | TCP Timestamp Option (TSval) | 32 | Низкая | Низкая (нарушение монотонности) |

### Механизмы каналов

- **ICMP Payload**: Данные помещаются непосредственно в payload ICMP Echo Request. Максимум 1472 байта на пакет (MTU 1500 - IP 20 - ICMP 8). Каждый пакет имеет 2-байтный length prefix.

- **IP ID**: 2 байта данных кодируются в поле IP Identification. Терминирующий пакет с ID=0xFFFF содержит общую длину. Носитель -- ICMP Echo Request.

- **TCP ISN**: 4 байта данных кодируются в TCP Sequence Number. SYN-пакеты с инкрементируемым destination port. Терминация: sport=65535.

- **DNS QNAME**: Данные base32-кодируются в поддомены DNS-запросов. Суффикс домена настраиваемый (по умолчанию `cdn-cache.net`). До 30 байт на пакет.

- **TCP Timestamp**: 4 байта данных кодируются в TSval TCP Timestamp Option. Терминация: tsecr=1.

## 4. Криптография

- **Алгоритм шифрования**: AES-256-GCM (NIST SP 800-38D)
  - Ключ: 256 бит (32 байта)
  - Nonce: 96 бит (12 байт), уникальный для каждого сообщения
  - Тег аутентификации: 128 бит (16 байт)

- **Формирование ключа**: Argon2id (RFC 9106)
  - Time cost: 3
  - Memory cost: 64 МБ
  - Parallelism: 1
  - Salt: 128 бит

- **Целостность данных**:
  - CRC32 на каждый фрагмент
  - SHA-256 всего payload (хранится в первом фрагменте)

---

## 5. Протокол фрагментации NST

Заголовок каждого фрагмента (17 байт):

| Смещение | Размер | Поле |
|----------|--------|------|
| 0 | 4 | Magic: `NST\x00` |
| 4 | 4 | Номер последовательности (uint32 BE) |
| 8 | 4 | Общее число фрагментов (uint32 BE) |
| 12 | 4 | CRC32 данных (uint32 BE) |
| 16 | 1 | Флаги (FIRST=0x01, LAST=0x02, NACK=0x04) |
| 17 | N | Данные |

Первый фрагмент дополнительно содержит 32-байтный SHA-256 хеш оригинального payload.

## 6. Модуль обнаружения

### 6.1 Статистические методы

| Метод | Что проверяет | Порог |
|-------|--------------|-------|
| Хи-квадрат | Равномерность распределения значений полей | p < 0.05 |
| KS-тест (IPD) | Экспоненциальность межпакетных задержек | p < 0.05 |
| Энтропия Шеннона | Нормализованная энтропия значений полей | > 0.95 |
| Регулярность IPD | Коэффициент вариации задержек | CV < 0.1 |
| Последовательность IP ID | Доля последовательных пар | ratio < 0.3 |
| Монотонность TSval | Доля нарушений монотонности | > 20% |
| Энтропия DNS QNAME | Энтропия символов + длина меток | H > 4.3, len > 25 |
| Размер ICMP payload | Средний размер payload | > 100 байт |
| Энтропия байт payload | Биты/байт в payload | > 7.0 |

### 6.2 Машинное обучение

- **IsolationForest** (unsupervised): 100 деревьев, contamination=0.05. 9 признаков: значение поля, дельта, IPD, размер пакета, скользящие средние/std, энтропия payload, длина payload.

- **RandomForest** (supervised): 100 деревьев, max_depth=10. Обучается на размеченных данных (normal=0, stego=1). Используется в мониторинге для оценки точности классификации.

### 6.3 Сигнатурный анализ

- Поиск magic-байтов NST-протокола (`NST\x00`)
- Поиск паттерна length-prefix + magic
- Base32-паттерны в DNS QNAME
- Маркеры терминации DNS

### 6.4 Анализ содержимого (обнаружение вредоносных вложений)

Сканирование извлечённых данных на наличие:

| Категория | Сигнатуры |
|-----------|----------|
| Исполняемые файлы | MZ (PE/Windows), ELF (Linux) |
| Скрипты | Shebang (`#!/bin/`), PowerShell, cmd.exe |
| Веб-атаки | `<script>`, `eval()`, `exec()` |
| Шеллкод | NOP-sled (`\x90`*8), INT3 sled |
| Архивы | ZIP (PK), GZIP, RAR |
| Документы с макросами | OLE2 (Office), PDF |
| Обфускация | base64.b64decode |

### 6.5 Агрегация результатов

Общая уверенность (confidence):
- Статистические аномалии (>=50% тестов или сильный индикатор): +0.4
- ML аномалия: +0.3
- Сигнатурное совпадение: +0.3

Трафик считается подозрительным при confidence >= 0.4.

## 7. CLI-интерфейс

```
netstego send       -- Отправка данных через стегоканал
netstego receive    -- Приём и расшифровка данных
netstego detect     -- Анализ PCAP на скрытые каналы
netstego stats      -- Просмотр статистики сессий
netstego benchmark  -- Бенчмарк канала
netstego keygen     -- Генерация AES-256 ключа
netstego report     -- Полный отчёт: бенчмарки + графики + детекция
```

Команда `report` генерирует:
- JSON с результатами бенчмарков и мониторинга (`results/data/`)
- 6 типов графиков PNG (`results/charts/`)
- Summary-таблицы в консоль

## 9. Достоинства

1. **Полнота реализации** -- полный цикл от шифрования до расшифровки, включая реальную сетевую передачу через Scapy.

2. **5 стеганографических каналов** -- покрывает основные классы сетевой стеганографии: модификация заголовков (IP ID, TCP ISN, TCP TS), кодирование в payload (ICMP), кодирование в прикладном протоколе (DNS).

3. **Сильная криптография** -- AES-256-GCM обеспечивает конфиденциальность и аутентичность. Argon2id -- устойчивость к brute-force ключей.

4. **Многоуровневая детекция** -- комбинация статистических, ML и сигнатурных методов с анализом содержимого.

5. **Два подхода ML** -- unsupervised (IsolationForest) для неразмеченного трафика и supervised (RandomForest) для оценки точности классификации.

6. **Анализ вредоносных вложений** -- сигнатурный анализ payload на наличие PE, ELF, скриптов, шеллкода и других индикаторов.

7. **Двухуровневая целостность** -- CRC32 на каждый фрагмент + SHA-256 всего файла.

8. **Устойчивость к потерям** -- поддержка избыточности (N-кратное дублирование с перемешиванием) + дедупликация.

9. **Визуализация** -- автоматическая генерация 6 типов графиков для демонстрации результатов.

10. **Настраиваемость** -- конфигурируемые параметры (скорость, jitter, DNS-суффикс, параметры Argon2id, пороги детекции).

11. **269 тестов** -- высокое покрытие кода, включая интеграционные тесты всего pipeline.

## 10. Недостатки и ограничения

1. **Нет ARQ-протокола** -- при потере пакетов в реальной сети нет механизма повторной передачи (есть только пассивная избыточность). Флаг NACK определён, но не реализован.

2. **NST magic-байты** -- паттерн `NST\x00` детектируется тривиально сигнатурным анализом. Нет обфускации заголовка.

3. **Высокий overhead для каналов с малой ёмкостью** -- IP ID (2 байта/пакет) и TCP ISN/TS (4 байта/пакет) создают сотни пакетов для передачи килобайт данных.

4. **DNS канал** -- использование base32 создаёт характерный паттерн с высокой энтропией, легко детектируемый статистически.

5. **TCP Timestamp** -- нарушение монотонности TSval -- сильный индикатор стеганографии, детектируемый простым сравнением.

6. **Нет защиты от active warden** -- промежуточный узел может модифицировать IP ID, TCP SEQ или TSval, уничтожив скрытое сообщение.

7. **Нет поддержки потоковой передачи** -- весь файл должен быть доступен до начала передачи (нет streaming mode).

8. **IsolationForest обучается на каждом наборе** -- нет предобученной модели; каждый анализ обучает новую модель.

9. **Один nonce/ключ на сообщение** -- при передаче нескольких файлов ключ переиспользуется (nonce уникален, но при компрометации ключа все сообщения раскрываются).

## 11. Направления развития

### Краткосрочные (доработка)

1. **Реализация ARQ** -- использование NACK-флага для запроса повторной передачи потерянных фрагментов.

2. **Обфускация NST-заголовка** -- XOR маской, производной от ключа, для защиты magic-байтов от сигнатурного анализа.

3. **Forward Error Correction (FEC)** -- замена простого дублирования на коды Рида-Соломона для более эффективной коррекции ошибок.

4. **Предобученная ML-модель** -- сохранение обученного классификатора на диск и загрузка при анализе.

### Среднесрочные (расширение)

5. **Новые каналы** -- HTTP (заголовки, cookie), TLS timing, IPv6 Flow Label, QUIC spin bit.

6. **Адаптивное кодирование** -- автоматический выбор канала на основе типа сетевого окружения.

7. **Cover traffic generation** -- генерация маскирующего трафика для сокрытия стеганографических пакетов в общем потоке.

8. **Deep learning детекция** -- CNN/LSTM для анализа последовательностей пакетов.

### Долгосрочные (исследования)

9. **Протокол обмена ключами** -- интеграция Diffie-Hellman или аналогичного протокола для начального обмена без предварительного ключа.

10. **Multi-channel передача** -- одновременное использование нескольких каналов для повышения пропускной способности и устойчивости.

11. **Тестирование в реальных сетях** -- анализ поведения через NAT, файрволы, IDS/IPS-системы.

12. **Формальная верификация** -- доказательство свойств протокола (undetectability, robustness) с использованием модели Simmons.
